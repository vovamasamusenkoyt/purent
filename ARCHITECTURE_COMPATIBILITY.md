# Архитектурная совместимость PureNT

## Цель

PureNT стремится воспроизвести архитектуру Windows 7 SP1 x64 (NT 6.1, семейство сборок 7601) один к одному на уровне системных компонентов и их взаимодействия. Цель проекта — полная совместимость с софтом и драйверами, рассчитанными на эту версию Windows. Совместимость каждого компонента подтверждается запуском и сравнением поведения с эталонной системой.

## Правило размещения кода

У каждой функции должен быть тот же владелец, что в эталонной Windows. Если работу выполняет определённый EXE, DLL или SYS, соответствующая реализация PureNT должна находиться в модуле этого компонента. Сохраняем границы процессов, режим исполнения, цепочки вызовов и направление передачи данных.

То же правило действует для исходных файлов. Если по бинарнику и символам установлено, к какому внутреннему модулю относится функция, Rust-код размещаем в соответствующем модуле. Например, композицию окон размещаем в реализации DWM, а API создания и управления окнами — на уровне USER32 и Win32k согласно их ролям. Если исходная граница неизвестна, фиксируем подтверждённого владельца и восстанавливаем внутреннее деление по мере появления данных.

## Распределение ответственности

| Компонент Windows | Ответственность, которую воспроизводит PureNT |
| --- | --- |
| `ntoskrnl.exe` | Объекты, память, процессы, потоки, планирование, системные вызовы и ввод-вывод NT. |
| `ntdll.dll` | Пользовательский загрузчик DLL, Native API и переход в ядро для системных сервисов. |
| `USER32.dll` и `GDI32.dll` | Пользовательские интерфейсы окон, сообщений, диалогов и GDI с передачей работы соответствующему системному компоненту. |
| `win32k.sys` | Ядерная часть USER/GDI, управление окнами и вводом, перенаправление отрисовки в поверхности окон. |
| `dwm.exe`, `uDWM.dll` и `dwmcore.dll` | Пользовательский процесс DWM, логика оконных визуальных эффектов и композиция поверхностей в итоговый кадр. |
| `conhost.exe` | Пользовательский хост консоли, который обрабатывает консольный ввод и вывод. |
| `shell32.dll` | Функции оболочки, включая `ShellAboutW`. Диалог создаётся через оконные API и ресурсы. |
| `winver.exe` | Загружает локализованные строки, вызывает `ShellAboutW` и ожидает закрытия диалога. |

Пользовательское приложение или GDI формирует содержимое окна. Win32k обеспечивает перенаправление отрисовки, а DWM в пользовательском процессе собирает кадр из поверхностей и применяет эффекты. В целевой архитектуре реализация итоговой композиции находится в компоненте DWM. В PureNT пользовательский `dwm.exe` собирает кадр из обоев и поверхностей консоли и модального окна. DWM применяет размытие фона для стеклянных областей рамки. Win32k готовит поверхности и маску стекла, рисует указатель и выводит кадр через GOP. Консольный ввод и вывод проходят через `conhost.exe`, а текстовая поверхность формируется в Win32k. `shell32.dll` передаёт содержимое диалога в `user32.dll`, которая вызывает общий модальный сервис Win32k. Для совместимости с Windows предстоит заменить частные интерфейсы протоколами соответствующих компонентов и обеспечить изоляцию адресных пространств.

## Как подтверждаем соответствие

1. Фиксируем эталонный бинарник и сборку. Сверяем PE-импорты, экспорты и символы Microsoft. При необходимости прослеживаем путь вызова в IDA.
2. Реализуем функцию в её компоненте. Воспроизводим соглашения о вызовах, форматы структур, жизненный цикл объектов, порядок вызовов, коды возврата и поведение при ошибках.
3. Проверяем каждый путь на оригинальном приложении или драйвере. Для `winver.exe` проверяем всю цепочку от загрузки EXE и DLL до вызова `ShellAboutW`, обработки сообщений диалога и завершения процесса.
4. Отмечаем временные реализации и условия их замены. Для проверки архитектурного соответствия прослеживаем, какой компонент выполнил работу, через какой интерфейс он её получил и кто использовал результат.
