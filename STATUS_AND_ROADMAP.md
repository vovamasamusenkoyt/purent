# PureNT: Текущее состояние архитектуры и Roadmap развития

Документ фиксирует текущий статус реализации операционной системы **PureNT** (чистая реализация ядра Windows NT 6.1 / Windows 7 SP1 x64 на Rust `no_std`), результаты верификации запущенных оригинальных бинарных компонентов и детальный план дальнейших работ.

---

## 1. Что уже сделано и верифицировано

### 1.1. Загрузчик и окружение (`crates/purent-boot`)
- **UEFI 64-bit Bootloader**: Написан на чистом Rust под таргет `x86_64-unknown-uefi`.
- **Higher-Half Paging**:
  - Построение 4-уровневой таблицы страниц (PML4, PDPT, PD, PT).
  - Прямое отображение первых 512 ГБ физической памяти через 1 ГБ Huge Pages в нижнюю половину (`0x0000000000000000`).
  - Отображение адресного пространства ядра в верхнюю половину (`0xFFFFF80000200000`).
  - Раздельное отображение структуры `KUSER_SHARED_DATA` по каноническому NT-адресу `0xFFFFF78000000000`.
- **GOP (Graphics Output Protocol)**:
  - Автоматическое перечисление видеорежимов прошивки и согласование графического режима **1280×720 @ 32 bpp TrueColor** с линейным кадровым буфером.
- **LOADER_PARAMETER_BLOCK**:
  - Полное формирование структуры параметров загрузки: физическая база кадрового буфера, размер, stride, карта памяти, базовый адрес ядра и указатель на PML4 (`CR3`).

---

### 1.2. Базовая архитектура ядра (`crates/purent-kernel` & `crates/purent-hal`)
- **KPCR / KPRCB**:
  - Инициализация Processor Control Region (`Kpcr`) и Processor Control Block (`Kprcb`).
  - Привязка к регистру `GS` через MSR `IA32_GS_BASE` (`0xC0000101`).
  - Поля `CurrentThread` (`gs:[0x188]`), `NtTib.Self` (`gs:[0x30]`), `PrcbData` (`gs:[0x20]`).
- **Сегментация и прерывания**:
  - Таблица глобальных дескрипторов (GDT) с селекторами кода/данных ядра (Ring 0) и пользователя (Ring 3).
  - Сегмент состояния задачи (TSS) с указателем стека прерываний `RSP0`.
  - Таблица дескрипторов прерываний (IDT) на 256 шлюзов прерываний.
- **Управление памятью**:
  - **PMM (Physical Memory Manager)**: Битовый аллокатор физических страниц памяти (4 КБ).
  - **NonPagedPool**: Ядерная куча с блочным распределителем памяти. Подтверждена процедура очистки и повторного использования освобождённых стековых блоков.
- **Диспетчеризация объектов (`ob`)**:
  - NT Object Manager с заголовками объектов (`OBJECT_HEADER`), счетчиками ссылок и типами (`Directory`, `Device`, `File`, `Driver`).
- **Процессы, потоки и планировщик (`ps`, `ke`)**:
  - Структуры ядра `EPROCESS`, `ETHREAD`, `KTHREAD`.
  - Вытесняющий планировщик потоков с квантом времени 10 мс, тактируемый через Local APIC Timer.
  - Примитивы синхронизации ядра (`KeWaitForSingleObject`).
- **Системные вызовы NT (`zw`)**:
  - Механизм быстрых системных вызовов через инструкции `syscall` / `sysret`.
  - Инициализация MSR `IA32_STAR`, `IA32_LSTAR` (`0xC0000102`), `IA32_FMASK`.
  - Реализованы и протестированы системные вызовы: `ZwCreateFile`, `ZwWriteFile`, `ZwClose`.

---

### 1.3. Загрузчик бинарных драйверов Windows (`ldr`)
- Парсер PE-файлов с автоматическим наложением релокаций (`IMAGE_DIRECTORY_ENTRY_BASERELOC`).
- Загрузка в память ядра оригинальных бинарных драйверов Microsoft:
  - `null.sys` — устройство `\Device\Null`.
  - `fs_rec.sys` — распознаватель файловых систем.
- Заполнение таблицы `MajorFunction` драйвера (`IRP_MJ_CREATE`, `IRP_MJ_WRITE`, `IRP_MJ_CLOSE`).

---

### 1.4. Исполнение User-Mode и оригинального `cmd.exe`
- Переход в Ring 3 с переключением таблиц страниц пользователя.
- Запуск собственного нативного процесса `smss.exe`.
- **Запуск оригинального 64-битного Microsoft `cmd.exe` (Windows 7 SP1 x64)**:
  - Бинарник загружен в пользовательское пространство, разрешены импорты через слой совместимости `purent_win32.dll`.
  - Выполнена инициализация среды, консольный процесс вывел реальные баннеры и командную строку `C:\>`.

---

### 1.5. Оконная подсистема Win32k и стиль Aero Glass
- Полноэкранный композитор без нижнего бара в разрешении **1280×720**.
- Аутентичные обои Windows 7 Harmony на весь экран.
- Пиксель-в-пиксель рамка Aero Glass (565×347 px):
  - Матовый полупрозрачный градиент заголовка с белой линией блика (`#FEFEFE`) и контуром (`#323232`).
  - Скругления углов: верхние 8px, нижние 6px.
  - Плавающая капсула кнопок `[_][□][X]` (104×21 px) с **0.00** MAE расхождением по каналам относительно эталонного скриншота Windows 7.
  - Оригинальная 16×16 иконка `[C:\]`, извлеченная из ресурсов PE-бинарника `cmd.exe`.
  - Вертикальный и горизонтальный скроллбары с трёхрёберными ползунками и угловым size grip.
- **Изоляция копирайта**: Все бинарные ассеты темы и обоев вынесены в директорию `assets/`, защищенную правилом в `.gitignore`.

## 2. Анализ проблемы с курсором мыши

На текущем этапе курсор отображается в точке старта, но не перемещается при движении мыши на хосте. Причины:
1. **Состояние 8042 после UEFI OVMF**: Прошивка OVMF инициализирует контроллер клавиатуры/мыши 8042 для собственного меню. При передаче управления ядру очередь контроллера остается неоткалиброванной; требуется полный аппаратный цикл сброса мыши (команда `0xFF` Reset с ожиданием байтов `0xAA` и `0x00`).
2. **Режим относительных координат в QEMU**: Стандартный PS/2-драйвер принимает дельты (dx, dy). В оконном интерфейсе GTK/SDL хоста это требует явного захвата мыши (клик внутри окна). Для бесшовной работы без захвата стандартом виртуализации является устройство с абсолютными координатами (`-device usb-tablet`).

## 3. Детальный Roadmap (Что предстоит сделать)

```
[P0] Интерактивный ввод  ──►  [P1] Win32 Console API  ──►  [P2] VFS и Файлы
  • Рабочая мышь               • ReadConsoleW / WriteConsole • Драйвер FAT32 / NTFS
  • Клавиатура PS/2            • Очередь сообщений Win32    • Команды dir, type, cd
  • Перетаскивание окон        • Менеджер окон (Z-Order)    • Запуск утилит с диска
```

### Этап 1: Интерактивный ввод (P0)
- [ ] **Оживление курсора мыши**:
  - Вариант А: Добавление полного цикла сброса контроллера 8042 (сброс `0xFF`, чтение `0xAA`, `0x00`, установка частоты опроса `0xF3 200` и разрешения `0xE8 3`).
  - Вариант Б: Подключение эмуляции абсолютного позиционирования (USB Tablet) для плавного перемещения курсора без захвата экрана.
- [ ] **Перетаскивание и интерактивность окна**:
  - Проверка попадания курсора (Hit-testing: `HTCAPTION`, `HTCLOSE`, `HTMINBUTTON`, `HTMAXBUTTON`).
  - Плавное перемещение окна мышью с сохранением и восстановлением фонового изображения под окном.
- [ ] **Драйвер клавиатуры PS/2**:
  - Обработка прерывания IRQ1 (порт `0x60`, вектор `0x21`).
  - Декодирование сканкодов клавиш (Scancode Set 1 / Set 2) с поддержкой Shift/Caps/Enter/Backspace.
  - Передача вводимых символов в активный терминальный буфер `cmd.exe`.

---

### Этап 2: Расширение среды Win32 Console Subsystem (P1)
- [ ] **Реализация базовых Win32 API в `purent_win32.dll`**:
  - `GetStdHandle` (`STD_INPUT_HANDLE`, `STD_OUTPUT_HANDLE`, `STD_ERROR_HANDLE`).
  - `WriteConsoleW` / `WriteConsoleA`: прямой вывод текстовых потоков в буфер окна `win32k`.
  - `ReadConsoleW`: блокирующее чтение символов из очереди ввода клавиатуры.
  - `SetConsoleCursorPosition`, `GetConsoleScreenBufferInfo`.
- [ ] **Многооконность и оконные сообщения**:
  - Цикл выборки сообщений `GetMessageW` / `DispatchMessageW`.
  - Диспетчер Z-order: переключение активного окна кликом, наложение полупрозрачных рамок.
  - Возможность открыть второе окно (например, `notepad.exe` или тестовый процесс).

---

### Этап 3: Файловые системы и дисковый ввод-вывод (P2)
- [ ] **Драйвер блочного устройства (AHCI / IDE)**:
  - Инициализация контроллера диска в QEMU через порты или MMIO.
- [ ] **VFS и монтирование томов**:
  - Монтирование виртуального диска с файловой системой FAT32 или NTFS.
  - Поддержка системных вызовов `NtOpenFile`, `NtReadFile`, `NtQueryDirectoryFile`.
  - Полноценная работа встроенных команд `cmd.exe`: `dir`, `type`, `copy`, `mkdir`.
